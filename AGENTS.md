# New York Focus interactive

This repo is one reader-facing interactive. It is served at `https://nysfocus.com/interactives/<slug>/` (slug in
`interactive.json`) by the separate `nyf-interactives` Worker, from this repo's Cloudflare Worker (static assets from
`site/`, settings in `wrangler.jsonc`; the county elections dashboard is the one Pages project). `README.md`
has the full checklist and setup; this file is the short version for AI coding agents (Codex and others read it
directly; Claude Code reads it through `CLAUDE.md`).

## Rules
- Be concise; test claims before asserting them.
- Run `npm test` before every commit. It must pass, and never weaken `scripts/check.mjs` to make it pass.
- The site lives in `site/`. Links are relative (never start with `/`); every page is `…/index.html` in its own folder;
  canonical and `og:url` are the page's nysfocus.com address.
- `sitemap.xml` is generated by `npm run build`. Don't edit it.
- Keep `_headers` (noindex) as it is: the router removes it on nysfocus.com, and it keeps the `workers.dev` copy out of
  search.
- No secrets in the repo, ever. If server code needs a key or token, Kyle enters it as a Worker secret. Never handle the
  key, print it or log it.
- Server routes: the site stays plain static files in `site/`; server code, only if the project needs it, goes in
  `worker/` (`main` in `wrangler.jsonc`), with only what's deployed there: its tests and fixtures go in `test/`, run by
  the `test:project` script (CI runs it on every PR). List the routes in `assets.run_worker_first` so static pages are
  served without running the code (a live-data project may run it on its pages to write how fresh their data is into
  them, any failure serving the page as built: README › Server routes). The router strips `/interactives/<slug>`, so
  routes are the Worker's own paths.
  - Routes readers' browsers call are GET only (the one exception: a route the router lists for POST, such as a
    newsletter sign-up, which it allows only from a nysfocus.com page, with a shared secret the route checks).
  - A route that writes (an ingest, an admin action) checks a secret token (a Worker secret Kyle sets) in the
    `Authorization` header, is never cached, and is reached at the Worker's own `workers.dev` address (nysfocus.com is
    GET only). It's never called from a reader's browser; if an operator's browser posts to it (a script on a results
    site), allow CORS for that one origin only, including the preflight and every response, errors too.
  - Previews have none of production's vars, bindings or secrets: give them safe values in `wrangler.jsonc` › `previews`,
    and make the code cope with what's missing (a 404 or 503, not an exception).
  - A timeout on every outside call, failures not cached, and never log what readers type or what's posted (queries,
    addresses, URLs, bodies): log the provider or route and the status only.
  - (The Pages project's Functions, in `functions/`, follow the same rules.)
- Brand: style with the variables and shared classes in `site/brand.css` (README › Brand; `site/brand.js` for its
  tooltips), and keep the font kit `<link>`, with `referrerpolicy="origin"`, on every page. The nysfocus.com header and footer come from `brand/`
  (`npm run build` inserts them); never edit them in the pages. Update them with `npm run footer:sync`.
- The shared `<head>` tags (icons, social) come from `brand/head.html`, inserted by `npm run build`; edit them
  there, never in the pages.
- Never launch a page without an SEO `<title>` within 580px, a meta description within 920px, and a 1200×630 link-card
  image (`og:image`, with alt text) of its own; `npm test` enforces these, and the placeholder `share.png` doesn't count.
  A new project's setup commit can use the setup card (`npm run card:setup`): `npm test` only warns about it, and
  `npm run check:launch`, which must pass before the project's router entry goes live, fails on it.
- Speed: anything a script draws after load starts in the page at its final size (render it in the build, or reserve the
  space), so nothing shifts; every `<img>` has `width` and `height`; a page stays under 500 KB of HTML; hidden panels draw
  their content when first opened (README › Speed).
- Every page keeps the analytics block from the template (Plausible and Google Tag Manager, the same as nysfocus.com). Don't add other trackers, ad scripts or third-party embeds without asking.
- Don't change `nyf-interactives` from here. Launches and routing are PRs there, reviewed by Kyle.

## Working together
Several people, each with their own AI agent (Claude Code, Codex…), change interactives independently: the growth team (which owns product) on
every project, and editorial, leadership and others as a project needs. Anyone may change any part of a project; the
people decide among themselves when to loop each other in. What keeps everyone, and every agent, in sync is that every
change is logged in the repo:
- **Start every session up to date:** `git checkout main && git pull`, then read what changed since you last worked
  (`git log --oneline -15`, the descriptions of the merged PRs, and Decisions below). Work on your own branch and open a
  PR. A person may merge any PR once its checks pass and it's up to date with `main` (no conflicts): a New York Focus
  staff member, or, on a project done with a third party, someone from that partner working on it. No AI tool (Claude
  Code, ChatGPT Codex or any other) merges on its own: only when one of those people explicitly tells it to. A merge to `main` publishes to readers, so
  check the live page afterwards.
- **Every PR description says what changed and why,** and how it was tested: it's the record the next person reads.
- **Log lasting decisions.** When a PR makes a lasting call (a design, wording, data or technical choice others should
  keep), add a dated line with who made it to Decisions in the same PR (project decisions under "This project" below).
  To change a decision, replace its line in the PR that changes it, rather than undoing it silently. If you're asked
  to do something that would undo a listed decision, say so before doing it, so the person can decide whether to
  check with whoever made it.
- **Shared files** (listed in `template.json`) are changed in `nyf-interactive-template`, never in a project;
  `npm run template:sync` then brings them into each project (a weekly check opens an issue when one is behind).
- **Generated files** (built pages, `sitemap.xml`, link-card images) are never merged or edited by hand: merge the
  sources, then rebuild.
